## 시험 환경과 결과

Node.js 24.19.0, Windows, Playwright Chromium 및 WebKit, 모바일 viewport 390×844 CSS px를 사용했습니다. 320·430px는 보조 폭입니다. 이 환경은 Chrome·Safari 계열의 자동 브라우저 시험이며 실제 iPhone·Android 시험과 구분합니다.

최종 실행 결과:

- 정적 검사 `npm run lint`: 오류·경고 없음
- 규칙·콘텐츠 회귀 시험 `npm test`: **31개 통과**
- 모바일 시험 `playwright test`: **22개 통과** (Chromium 11개, WebKit 11개, 42.6초)
- 프로덕션 `npm run build`: TypeScript 검사와 Vite 빌드 통과, 오프라인 앱 자산 6개 생성
- 주요 11개 화면의 axe WCAG A·AA 자동 검사: 위반 없음
- 320·390·430px 주요 화면과 200% 글자 확대에서 가로 스크롤 없음

화면 캡처는 `artifacts/`, Playwright 보고서는 `playwright-report/index.html`에 있습니다. 자동 접근성 검사는 실제 화면 낭독 시험을 대신하지 않습니다.

## 확인 중 수정한 문제

- Vite 정적 파일의 `Vary` 헤더 차이 때문에 Chromium에서 오프라인 모듈이 조회되지 않았습니다. 빌드가 지정한 동일 출처 자산만 `ignoreVary`로 조회하도록 수정했습니다.
- 하단 비활성 탭의 글자 대비가 4.5:1보다 낮아 더 짙은 색으로 수정했습니다.
- WebKit의 초기 화면 초점 이동이 사용자 입력을 가져가는 문제를 막았습니다. 화면 이동 시에만 본문에 초점을 이동합니다.
- 뒤로가기의 스크롤 복원을 React 화면 반영 이후로 옮겼습니다. 시트 닫기는 페이지 스크롤을 초기화하지 않습니다.
- 저장 거부 시 세션 값이 기존 디스크 저장값보다 우선하도록 수정했습니다.
- 다이너마이트로 탈락하면 감옥 판정 입력을 요구하지 않습니다. 두 생존자의 맥주처럼 충분한 조건이 이미 알려진 경우 불필요한 질문을 생략합니다.

## 출시 전 사용자 확인

기획서의 초보자 5명 준비 안내 관찰과 대표 질문 10개의 첫 결론 도달 중앙값 10초 목표는 실제 사용자 시험을 수행해야 확인할 수 있습니다. 아직 측정하지 않았습니다. 자동 검색 함수 시험은 100회 평균 100ms 미만을 확인하며, 실제 사용자 응답 시간이나 실기기 성능으로 일반화하지 않습니다.

실제 iPhone Safari·Android Chrome에서 검색 키보드와 하단 탭, 주소창 높이 변화, 안전 영역, VoiceOver·TalkBack, 처음 다운로드 후 비행기 모드, 새 버전 업데이트를 확인하세요. 자동 검사 통과를 이 수동 확인의 완료로 표현하지 않습니다.
